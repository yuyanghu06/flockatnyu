No calendar date or closing time was supplied, so the implementation has no automatic expiry and does not invent an operating date. The popup is currently enabled through one flag. ## What was imported and how it reaches the site

1. [src/assets.js](../src/assets.js) already includes the shared source file [tile-1_1.glb](../assets/yuyang-site-3d-assets/models/buildings/city-tiles/tile-1_1.glb). The existing `GLTFLoader` and `MeshoptDecoder` in [src/main.js](../src/main.js) load this city tile in the Washington Square coordinate system. The tile, loader and decoder predate this popup and serve other map geometry.
2. [src/go-greek-popup.js](../src/go-greek-popup.js) is the central, pure-data manifest. It contains `enabled`, the stable ID, matching tile name, displayed name/description and fixed camera values. It imports no model, Three.js module or runtime service.
3. Only when the manifest is enabled **and** the tile name matches, `loadJob()` in `src/main.js` dynamically imports [src/broadway-683.js](../src/broadway-683.js). `createBroadway683Model(tileRoot)` reads the source geometry before any removal and requires exactly 70 selected source triangles from BIN1008629. The footprint and source Y range 4.148–59.608 meters isolate the south corner tower and its rooftop enclosures. The taller northern tower and adjoining low podium stay ordinary city context.
4. The builder retains all 70 selected triangles first, preserving their original positions and winding, then adds deterministic procedural facade and roof geometry. All detail is baked into one vertex-colored, double-sided `Mesh`, with an identity transform and world/map coordinates. Six shared ground triangles crossing the selection boundary remain in the source tile. The unexposed north wall has source geometry only above approximately 34.51 meters, and detail respects that boundary.
5. After successful construction, the existing `removeReplacedBuilding()` in [src/geometry.js](../src/geometry.js) removes those same 70 triangles **from the loaded tile in memory**. A count check reports unexpected removal. No source GLB or export is modified, and no duplicate selected shell is left in the context tile.
6. The model is passed to the existing `registerLandmark()` in `src/main.js`, which registers the complete object for picking, static resource handling, atmosphere, the landmark root registry and shared selection effects. [src/config.js](../src/config.js) includes its displayed `Go Greek` record only while enabled. [src/building-views.js](../src/building-views.js) similarly includes the popup camera only while enabled: 13 degrees azimuth, 48 degrees polar angle and 0.9 height scale.
7. The existing shared UI in `src/main.js` builds the selector from `buildings` and fills `#building-name`/`#building-description` from that record. [src/map-interactions.js](../src/map-interactions.js) and [src/camera-focus.js](../src/camera-focus.js) handle selection and framing. [src/landmark-effects.js](../src/landmark-effects.js), [src/landmark-outline.js](../src/landmark-outline.js) and [src/landmark-footprint.js](../src/landmark-footprint.js) apply the same steady white overlay, outline and footprint used by other landmarks. Facade, cornice, planting and tank all belong to the complete selectable mesh. These shared components were not customized for the popup. There is no popup-specific CSS. When registration is disabled, none of this shared selectable-landmark behavior is attached to the context tower.

The single user image informs warm brick, a pale three-storey masonry base, rustication, 320 narrow sash windows, 15 generic storefront openings, stone sills/lintels and a layered crown. The roof has seven planters, eight small trees, 38 shrubs, 38 paving slabs and one cylindrical water tank with supports, metal hoops and a tan lid. Source massing and roof enclosures are preserved; window layout, planting, service elevations and tank dimensions are approximations, not surveyed dimensions. Map labels and tenant signs are not reproduced. Metadata and counts are in the mesh's `userData`; the complete model has 34,118 triangles.

This addition does **not** import a separate custom GLB, texture, image, font, CSS file or npm dependency. It uses the existing shared city tile and installed Three.js geometry helpers. The model itself adds no backend endpoint or provider integration. The later authorized catalogue addition is a separate owner-only data migration, described below. No deployment or hosted migration success is implied by the local files.

Applied migrations remain immutable; do not run a bulk database push to activate this isolated seed. The orchestrator applied only037 through Supabase MCP after independent checks; unrelated036 remains unapplied. A failed or unusable request still shows unavailable. The catalogue row alone creates no event, attendance or personal activity. The frontend enable switch controls only visuals and never inserts, deletes or hides backend activity records.

## Disable after the popup

1. In [src/go-greek-popup.js](../src/go-greek-popup.js), change only `enabled: true` to `enabled: false`.
2. Run `npm run build` from the repository root. Use the normal separately authorized release workflow to publish that rebuilt version if needed; changing a local flag does not change an already deployed website.
3. Reload the rebuilt site. Expect nine selectable landmarks, no Go Greek selector/card entry or camera preset, and no runtime request for the popup model module. The matching city tile remains fully loaded as ordinary non-selectable context, including all 70 source triangles: the dynamic import, builder, source removal and registration are skipped together. The original surrounding complex is unaffected. Disabling this frontend flag does not delete the separate backend catalogue row or any activity/relationship attached to it.

The flag disables runtime features; the bundler may still emit an unused dynamic model chunk into the build directory. A chunk present on disk is not proof it was requested or executed. The source model and manifest remain available for later reactivation. Do not implement date-based expiry until a real date/time and timezone have been chosen.
