- Decisions: proposals only. Persist normalized event facts, source IDs/links, field provenance, explicit RSVP/identity matches, building IDs, sync checkpoints and durable jobs; reconstruct bounded model context for each run. Do not depend on perpetual chat history. A five-minute Railway sweep is an initial option; event-driven triggers plus scheduled reconciliation are the longer-term design. - Proposed boundaries: source-specific signup adapters, API-first access with controlled read-only browser fallback, no assumption that public pages expose private guest lists. Treat external content as untrusted; restrict domains/redirects/network destinations. Stable provider IDs and verified identity links prevent name-based merges. RSVP is intent, check-in is attendance, physical location requires separate opt-in presence. Preserve source visibility when publishing to shared maps/calendars. Dedicated managed calendar, field ownership and explicit notification policy avoid overwriting human edits or sending unintended invites.
- Proposed reliability: database queue/outbox, unique action keys, worker leases/timeouts, retries and bounded run budgets; commit event updates and pending actions together; deterministic Calendar IDs/provider mappings prevent duplicate creates after ambiguous failures. Checkpoints advance only after durable processing. Process new messages plus edits/deletions, periodically reread known event sources and reconcile signups/cancellations. Failed/inaccessible reads must not clear attendees or imply cancellation. Surface partial/stale state and repeated failures. Google sync tokens are source-scoped and invalidation rebuilds only that connector view.
