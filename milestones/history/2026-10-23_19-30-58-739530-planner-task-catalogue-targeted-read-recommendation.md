# Small task catalogue and targeted saved-task reads recommended

- Acting role / scope: planner specialist; read-only recommendation for the user's “How should we fix?” question. No edits, inference or external calls.
- Evidence: current task store and pipeline still have five whole-snapshot list calls, covering startup, both finish checks and two follow-up transition reads. Previous recorded aggregation benchmark is16.5seconds for131tasks/about12.4MB.
- Recommended design: small scoped catalogue for selection; exact complete task snapshots only for selected tasks, matching current-original coverage candidates and relevant completion checks. Catalogue carries IDs, source scope, timestamps, input UUIDs, eligibility and bounded request summary/targets. A catalogue entry cannot grant a read receipt or write/delete authorization. Selected snapshots retain current complete-original/content/version checks, compact/full model views and fragment proof.
- Preservation requirements: retain all authorized existing IDs privately, including mechanical tasks; only eligible model tasks enter the model catalogue. Preserve initialTaskIds and construct followupScope from catalogue IDs, independently of loaded snapshots. Load an existing generated task ID before merge/save. Checkpoint touched/loaded work only; untouched rows remain intact. Reread full snapshots for exact relevant IDs at finish; no new digest architecture is needed.
- Modules / migration: add new task-service catalogue/exact-read SQL operations in a new migration, preserve applied migrations; adapt task-store, staged pipeline and bounded diagnostics. Keep current limits and isolated service operations.
