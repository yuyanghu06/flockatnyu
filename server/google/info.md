# Google connectors

This server-only folder connects one explicitly authorized club Google account to the Railway assistant. It uses Google OAuth refresh tokens and fixed Gmail/Drive/Calendar REST origins. It does not depend on a desktop MCP session.

- `config.js`: secret configuration, default read-only scopes and optional Calendar scopes.
- `oauth.js`: official Google auth library setup, scope/account verification and safe error codes.
- `client.js`: bounded Gmail search/read and Drive search/text-export operations. No attachments, mail sending, file updates or arbitrary URLs.
- `../../tools/google/index.js`: model tool definitions and an explicit server-owned `principal.googleAccess === true` gate. Bot/account credentials alone never grant a member access.

Configuration status, successful OAuth verification, and principal access are separate. Status inspection performs no Google request. Revoked tokens require consent again. Search excerpts and read results are untrusted source content, with original links and partial-content labels. Sheets export reads only the first sheet; unsupported binary files return metadata. Setup is in [the connector guide](../../docs/google-connector.md).

## Gmail source-event subscription

- `subscription.js` implements the Gmail watch baseline, daily renewal, history catch-up and authenticated Pub/Sub notification handling. History IDs remain decimal strings and comparisons use BigInt. A notification wakes reconciliation; its history ID never overwrites the durable cursor.
- `subscription-store.js` calls service-only `agent_subscription_get_state` / `agent_subscription_cas_state` RPCs from migration019. The `subscription:gmail:<source UUID>` state contains mailbox identity, cursor, resumable page token and within-page offset/fingerprint, watch expiration and a bounded lease. Raw email bodies belong only in the shared two-column input cache.
- `subscription-app.js` exposes `/healthz` and `/webhooks/gmail`. Push authentication verifies the Google OIDC signature, issuer, exact audience, verified service-account email and expiration before persistence. Body/base64/API/page/message bounds fail closed. Gmail base64url and Pub/Sub standard base64 are both accepted only with canonical encoding and bounded decoding. Optional rejection diagnostics emit fixed stage/reason codes and scalar type labels; the CLI logs only the fixed reason and allowlisted scalar type classification, rate limited to once per reason per minute. No headers, tokens, mailbox values or payload content enter these diagnostics.
- `subscription-cli.js` supports `status`, `watch`, `renew`, `sync`, and `serve`. Run with Node's `.env` and `.env.google` loaders. `serve` runs a serialized five-minute reconciliation timer and renews watches daily; SIGTERM/SIGINT abort active background work. No LLM is called by collection.

Activation requires `GMAIL_EVENTS_ENABLED=true`, existing Google OAuth configuration, `GOOGLE_PUBSUB_PROJECT_ID` (defaults to `techflock`), a full `GOOGLE_PUBSUB_TOPIC`, `GOOGLE_PUBSUB_AUDIENCE` matching the public HTTPS webhook audience, `GOOGLE_PUBSUB_PUSH_SERVICE_ACCOUNT`, and `AGENT_GMAIL_SOURCE_ID` as a UUID in the shared `ASSISTANT_ALLOWED_SOURCE_IDS` (legacy alias accepted). Optional `GOOGLE_PUBSUB_SUBSCRIPTION` pins one full subscription name. Supabase service credentials and migrations018/019 are required. The OAuth account must match `GOOGLE_EXPECTED_ACCOUNT_EMAIL`, with the existing Gmail/Drive read-only scopes; there is no scope expansion.

Cloud topic/IAM/authenticated push subscription creation and the public endpoint deployment are separate activation steps. Gmail's publisher identity needs publish permission on the topic. Existing OAuth readiness alone does not establish Pub/Sub readiness. A first watch starts at its returned baseline and does not backfill the mailbox. Renewal preserves the existing cursor; completed pages preserve a continuation token. A page larger than one run resumes from a saved offset only when the SHA256 fingerprint of its sorted message-ID/revision pairs matches; changed page contents replay with stable deduplication IDs. Failed fetches or enqueues best-effort checkpoint preceding successful entries without advancing past the failed input. Only the offset and fingerprint are stored, never raw mail or a message-ID list. A stale history cursor becomes `resync_required` and remains unchanged until an explicitly designed resync is performed. Oversized full MIME responses fall back to a bounded raw metadata response with the distinct email_received_metadata event type; body-based actions then require a later authorized Gmail read tool. If metadata is also oversized or unavailable, the cursor remains unchanged. Deleted-before-fetch messages, failed enqueues and unavailable API/state calls also retain the cursor for retry or operator resolution. Collection retains full bounded Gmail message JSON, including original headers and MIME parts, inside the generic cache envelope. This adds no mail sends, mark-read operations, file writes, calendar updates or model prompts.

Signed Google notifications were observed reaching `notification_history_type` rejection after successful authentication/envelope/encoding validation. The diagnostic established a non-string value, without inspecting its value; numeric origin remained an inference pending live acceptance. Notification hints now accept positive safe-integer JSON numbers by exact conversion to decimal strings. Unsafe integers, fractional/zero/negative/nonfinite numbers and other types remain rejected. Existing decimal-string hints retain BigInt comparisons, and provider API cursors remain string-only. Notification hints never replace the persisted cursor.

Gmail collection is independent of AGENT_AUTOMATION_ENABLED and other model-worker configuration. Disabling the model worker preserves ingestion; disabling GMAIL_EVENTS_ENABLED stops the collector.

## Update agent Calendar connection

`calendar-config.js` requires an explicit GOOGLE_CALENDAR_ID. `calendar-client.js` verifies account, Calendar scopes and the exact target’s writer/owner role before mutation; `../../tools/calendar/` exposes bounded event reads and Miro-sourced managed upsert/cancellation. Stable source-based IDs reconcile retries; ownership/hash markers and ETags protect human changes. Model arguments cannot choose another calendar. There are no attendees, invitations, recurrence or arbitrary deletes.

The existing read connector and Gmail collector keep their read-only scope requirements. `google-connect.mjs --calendar` adds Calendar event and calendar-list access only when explicitly selected. Credentials remain in ignored local files/service secrets. Calendar connection does not enable the update agent or add Calendar writes to the chat agent.
