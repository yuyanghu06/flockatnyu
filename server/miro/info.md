# Live Miro connection

mcp-config.js fixes the official origin, board/team scope and resource limits. mcp-client.js uses the official SDK with a three-read-tool allowlist, bounded HTTP/SSE and sanitized errors. mcp-auth.js owns application OAuth credentials, private atomic storage, refresh rotation and interprocess locking. scripts/miro-connect.mjs performs local consent; developer Codex authentication is separate.

store.js exposes only the service-only authorizedBoard registry RPC. Migration030 moves the old board enable/team metadata into knowledge_sources and deletes snapshot storage/sync routines. No REST client, collector, CLI or cached-content fallback remains. ../tools/miro/mcp.js supplies the same scoped reader to chat and update agents. No Miro writes or automatic source expansion are available. See ../../docs/miro-sync.md.

navigation.js contains shared, board-scoped structural hints for chat and update prompts. It performs no I/O and grants no source or mutation access. Revalidate section/month/legend context live; copied years remain ambiguous until corroborated.

Production web is the sole rotating OAuth owner on a private persistent volume. token-broker.js authorizes worker access-token requests separately from browser sessions; workers contact official MCP directly without refresh credentials. Queue is bounded to64waiting operations and canceled waiters reject promptly. Local OAuth copies must not continue refreshing after ownership transfer.

quota.js shares metadata-only organization counters through the existing service-only subscription state CAS RPCs under one fixed key. Production enables budgeting by default; MIRO_MCP_BUDGET_ENABLED accepts only true/false. Actual tools/call requests reserve before send and are never refunded:80total/day,48background/day,12per background session, sessions start at least6hours apart and expire after10minutes. This protects32chat calls and leaves20Free-plan calls for outside clients. UTC midnight rolls counters over. Explicit upstream daily-quota error envelopes block both lanes until midnight; successful board content cannot trigger that classification. Store failure, malformed state or bounded CAS contention fails closed. No raw board content, credentials or provider errors enter this state. Tool initialization/listing is uncounted. The update adapter must call beginBackgroundBatch once before each preparation; chat uses the default lane.

Reservation sits at the physical SDK HTTP send boundary beneath origin validation. Broker401 retries and native OAuth replays each require their own slot; reaching the last slot prevents another replay. OAuth discovery/token exchange and MCP initialization/listing do not consume tool budget.

Miro MCP requests default to the shared 60-second source timeout; explicit `MIRO_MCP_REQUEST_TIMEOUT_MS` settings remain authoritative. Quota reservation and its subscription-state store also allow 60 seconds while preserving parent cancellation and fail-closed behavior. The separate post-denial exhaustion-accounting caller retains its five-second limit.
