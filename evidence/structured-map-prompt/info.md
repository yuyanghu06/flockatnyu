# Structured map records and update-agent prompt verification

Independent tester evidence for the shared storage contracts and actual worker prompt delivery. `initial-test-output.txt` retains the first combined198-test pass before the user clarified the two-hour current-presence expiry policy; presence-policy-test-output.txt retains the intermediate203-test pass after current-presence expiry was approved but before the separate event-duration policy. The final run/report supersede both intermediate runs for final acceptance.

The tests operate exclusively on synthetic provider responses and an in-memory PostgreSQL-compatible PGlite database loaded with actual migrations001–024. No cloud writes, model calls, deployment, production ingestion, map-write tool registration or presentation changes occur. No browser checks are required for this prompt/data-contract-only scope.

`tests/map-contracts.test.mjs` checks immutable machine-readable schema shapes, actual worker schema-checker compatibility, strict types/fields/bounds, flat exported examples through actual SQL, immutable applied migration hashes, identity/time/source semantic rejection, and unchanged runtime write privileges. `tests/update-agent-prompt.test.mjs` captures the real handler's provider request and checks that the actual system prompt contains the contracts, examples and supported behavior instructions, while unknown map actions and text-only completion claims preserve the queue.

These checks establish instruction delivery and structural/SQL behavior. They do not establish that an LLM will follow the instructions or autonomously perform map writes. Map tools remain unavailable. SQL and generic schema validation are intentionally distinguished: PostgreSQL string lengths count Unicode code points while the existing generic validator counts UTF-16 units; the SQL event title bound applies after btrim, which the generic schema documents for semantic enforcement. Database timestamps validate format, finiteness, ordering and named timezone existence; local-midnight all-day boundaries and offset/timezone coherence are additional prompt/future-tool rules, not current SQL guarantees. Source-access authorization remains independently enforced by existing/future trusted adapters, not these storage schemas.
