# M20 summary runner implementation

- Milestone / role / scope: M20 coder, dedicated Luna Responses provider and resumable summary runner. Exclusive new implementation files; no existing archive/config/store/schema/tracking edits.
- Starting state and inspected inputs: role/report templates, current milestone/to-do, Discord archive/memory/embedding modules, root's implementation assignment and storage coder's RPC contracts. Existing 779 groups and 108,828 originals are parent-provided hosted counts, not newly verified by this coder.
- Changed files: `server/discord/summary-config.js`, `summary-provider.js`, `summaries.js`, `summary-cli.js`, this evidence report.
- Implemented: exact `gpt-6-luna` nonstreaming Responses requests with `reasoning.effort=none`, strict JSON text format, `store=false`, 1,600 output tokens, no tools/images/downloads/embeddings. Every attempt obtains a durable reservation before dispatch and records actual or uncertain usage afterwards. Retries are limited to two transient retries. Refusals, incomplete/malformed/oversized output, foreign citations and invalid usage fail closed.
- Summary shape: seven arrays (`overview`, `decisions`, `actions`, `events`, `people`, `resources`, `uncertainties`) of `{text,messageIds}` findings. Citations are checked against supplied originals, and final Discord URLs are constructed from trusted job identities. Prompt distinguishes posting dates from event dates and treats originals/intermediate summaries as untrusted evidence.
- Resume/coverage: canonical original text and server-derived segments are paginated chronologically; exact segments are packed within 48 KiB without truncation. Map parts record every input segment independently from short finding citations. Recursive bounded reduction records child references. Final publication asks the database to verify full manifest/DAG coverage and current input fingerprint. Nested-key canonical serialization preserves part hashes when PostgreSQL JSONB reorders cached summaries or memory-group UUIDs change.
- Bounds: four concurrent jobs, 25 groups/100 attempts/600 seconds per run by default; fixed 48 KiB evidence, 32 KiB validated output, 30-second request timeout. Conservative request reservations include serialized instructions/schema and protocol margin, at documented $0.10 input/$0.50 output per million tokens. Initial operation cap $5, per-run cap $1; environment settings can lower cost caps. No cache pricing credit is presumed.
- CLI: `preview`, `run`, `backfill`; strict non-secret flags and UUID operation IDs. Reports expose only fixed statuses, counts, usage and operation IDs. SIGINT/SIGTERM abort dispatch; dispatch usage is committed without the already-aborted signal.
- Checks executed: all four new files passed `node --check`. Clean-environment `node server/discord/summary-cli.js run` exited 1 with `not_configured`. `node --test tests/discord-summary-provider.test.mjs` passed 19/19, rerun successfully after final cache/accounting changes. Parent reports 33 independent provider/runner checks passed; that broader report is parent/tester evidence, not a separately executed coder run.

A two-request run cap preserved both map parts; resuming the same operation with reordered cached JSON keys reused those parts and dispatched only the final reduction. A 429 followed by success reserved/committed both attempts; malformed response JSON made one request and failed without retry. These fixtures used injected fetch/store objects and made no network/model calls.
