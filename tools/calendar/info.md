# Fixed-target Calendar tools

These shared server tools list/read events and idempotently upsert/cancel Miro-sourced events in the explicit `GOOGLE_CALENDAR_ID`. No model argument can select a calendar. The chat agent receives no Calendar grant automatically; the trusted update runtime supplies `calendarAccess`, matching `calendarId`, shared source allowlist and `calendarSources` board/source pairs.

`createCalendarTools({client})` supplies definitions with bounded argument schemas and executable records. Reads have `readOnly:true`; writes have `idempotent:true`. Its `execute({name,arguments,principal,signal})` dispatcher and each record's `execute(args,{principal,inputIds,idempotencyKey,signal})` use the same validation. Results never exceed16KiB. Triggering queue IDs are separate from durable event identity.

Current writes accept only `sourceKey=miro:<boardId>:<itemId>` and the exact canonical original Miro item URL. Gmail/Discord inputs may trigger board review but do not independently authorize Calendar writes. `server/google/calendar-client.js` fixes target/account/scopes, checks exact-calendar ACL, uses deterministic event IDs and private ownership/source/hash markers, reads before changing, preserves unmanaged/human-modified events and uses ETag conditional patches. Upstream failures expose safe codes. Cancellation marks only a matching managed event cancelled; missing rows never cause arbitrary deletes. Changed/tombstoned events without verifiable ownership fail closed.

Timed events require explicit RFC3339 offset and IANA timezone; all-day dates use an exclusive end. No attendee, invitation, recurrence, mail-send, Miro-write or calendar-management tool exists. Writes use `sendUpdates=none`. Additional OAuth consent is opt-in via `npm run google:connect -- --calendar --force`; ordinary connector consent remains Gmail/Drive readonly. Local implementation and mocked verification do not establish live Calendar permission or worker activation.
