# Fixed-target Calendar tools

These shared tools list/read and reconcile events in the fixed server-selected Calendar. No model argument can choose a calendar. The current worker receives exact authorized Discord/Gmail original grants from its trusted runtime; it has no Miro tools or automatic Miro reconciliation. Member Plans uses its separately pinned target and linked-person checks. The low-level client retains explicit Miro compatibility for other authorized callers; this does not expose Miro evidence to the worker.

`createCalendarTools({client})` supplies definitions with bounded argument schemas and executable records. Reads have `readOnly:true`; writes have `idempotent:true`. Its `execute({name,arguments,principal,signal})` dispatcher and each record's `execute(args,{principal,inputIds,idempotencyKey,signal})` use the same validation. Read results stay within16KiB. Saved-write receipts use the separately bounded safe receipt projector; worker responses above its tool-message budget use existing ephemeral RAM fragments. Triggering queue IDs are separate from durable event identity.

Low-level explicit Miro compatibility accepts `sourceKey=miro:<boardId>:<itemId>` or stable native-table row keys `miro:<boardId>:<tableId>:row:<rowId>` and the exact canonical original Miro item URL. Explicit scheduled club events may also use discord:<guild>:<channel>:<message> with exact fresh live original grants and current policy rechecks. Personal study/presence/RSVP does not independently authorize Calendar writes; new-message corrections and cross-source conflicts defer. `server/google/calendar-client.js` fixes target/account/scopes, checks exact-calendar ACL, uses deterministic event IDs and private ownership/source/hash markers, reads before changing, preserves unmanaged/human-modified events and uses ETag conditional patches. Upstream failures expose safe codes. Cancellation marks only a matching managed event cancelled; missing rows never cause arbitrary deletes. Changed/tombstoned events without verifiable ownership fail closed.

Timed events require explicit RFC3339 offset and IANA timezone; all-day dates use an exclusive end. No attendee, invitation, recurrence, mail-send, Miro-write or calendar-management tool exists. Writes use `sendUpdates=none`. Additional OAuth consent is opt-in via `npm run google:connect -- --calendar --force`; ordinary connector consent remains Gmail/Drive readonly. Local implementation and mocked verification do not establish live Calendar permission or worker activation.

`chat.js` exposes the same list/read/create/batch-create/update/batch-update/delete definitions in every top-level and request-local catalogue. Tool visibility does not depend on user wording. The model interprets the current request and conversation, asks for ambiguous targets and ignores quoted or retrieved instructions. Generic or partial title matches cannot choose among multiple plausible events by result order, ranking or reading one candidate; mutations need a unique exact target or user-supplied distinguishing context. There is no Calendar intent parser or semantic execution gate. Backend execution still requires trusted Google access, the fixed target, valid arguments, request operation identity for creates and fresh request-local hidden revisions for edits/cancellation. Stateless mutations remain denied. This separate path may modify user-selected human-created events while leaving update-agent ownership/hash checks unchanged. Successful mutations return bounded canonical Calendar receipts. Recurring, attendee-bearing and special events remain unsupported. Calendar progress reports actual attempts and receipts, never inferred authorization.

Chat event sources carry a server-configured sourceId only when that UUID is allowlisted. This permits separately authorized map event provenance with exact eventId; selected Calendar fields do not authorize attendance or Calendar edits. The update adapter observes Calendar reads and checks fixed-target current access before map mutation.

`chat-batch.js` implements create_calendar_events and update_calendar_events for up to50rows per call. Creates accept canonical start/end or compact date/startTime/endTime/timeZone for timed rows; legacy date-only rows remain all-day. Supplied clocks are never moved into descriptions or dropped. chat-boundaries.js reuses the Calendar boundary validator, resolves local clocks through timezone offsets and rejects DST gaps/overlaps rather than guessing. Exact normalized title and boundary matches skip; same-title/date all-day versions of requested timed events require an in-place update. Duplicate scans retain20pages/window and100pages/batch bounds.

Bulk updates require exact event IDs from prior receipts or narrowed listings, internally read each exact ID for a fresh hidden ETag, reject unsupported rows and patch only supplied fields. Conflicts fail independently; shared Google access failures leave later rows unattempted. The client explicitly nulls incompatible date/dateTime/timeZone fields on Google nested PATCH conversions. Per-row receipts include actual boundaries/timezone and family-specific created/existing or updated/unchanged counts. Direct cancellation preserves earlier receipts; runner timeout/disconnection cannot guarantee a final reply, so retry reconciles actual state.

list_calendar_events now reads a bounded window with backend-managed pagination. The model schema has no pageToken and results expose no cursor. Query/window/resultMode/page size remain fixed through traversal; empty intermediate pages continue, exact event IDs deduplicate in first-seen order, and malformed or repeated cursors stop safely. Bounds are20pages,200events,14KiB of selected events and16KiB total result within one shared60second deadline plus parent cancellation. A valid prefix survives count/byte bounds or later transient failures as incomplete coverage; observed access/account revocation withholds retained content. Native clients recheck account/scopes/Calendar ACL after traversal. There is no cross-call cache.

Calendar list resultMode defaults full. identities requests only provider id/summary/start/end/status and projects canonical identity/timing/URL fields, excluding descriptions, location, source metadata and timestamps. Partial reads require narrower windows or queries, never another model-supplied token or an absence claim. Bulk edits still perform fresh exact reads internally. The low-level client.listEvents remains single-page with its original16KiB bound: batch duplicate checks retain their separate20pages/window and100pages/batch budgets.

Single, managed and batch mutation receipts use `../../server/google/calendar-receipt.js` to retain actual saved title, description, location, timing/timezone, status and safe ancillary provider fields through public/model projections. Explicit clears, missing fields and truncation/omission markers remain distinct; requested or prewrite fields never become saved facts. Internal duplicate scans alone request expanded receipt details; ordinary read/list payloads stay unchanged. Batch failure items retain sanitized local/provider metadata for operational logging; public receipt projection omits diagnostics. Exact IDs, hidden revisions, fixed-target and duplicate checks remain unchanged.

Batch projection uses deterministic detail/core/identity-only tiers when needed, preserving realistic saved names/times and all exact identities/outcomes while explicitly marking omitted detail. Repeated projection and duplicate native results preserve each tier; failure rows also omit requested display fields if required for the byte bound. Planning capability/progress summaries refer to per-row tool results instead of duplicating their bodies.

Worker club Calendar provenance accepts exact runtime-owned queued Gmail message grants alongside Discord. Gmail keys/URLs must match the observed original body and explicit source grant; snippets and model-supplied URLs cannot grant writes. Signed Member Plans participation remains a separate path. The worker no longer performs automatic Miro reconciliation; shared explicit Miro support for other callers remains.
